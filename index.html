02 How I work

Four principles I build by

Judgment that turns a demo into a system people depend on.

P.01

Production over prototypes

Models matter only when they survive real traffic, real latency budgets, real edge cases. I design for deployment from day one, not the notebook.

P.02

Legible by design

Interpretability is built in, not bolted on. SHAP, LIME, and attribution live in the architecture, so every decision stays auditable.

P.03

Optimized for the edge

Quantization, ONNX, and TF Lite, tuned across Snapdragon and Exynos. Full models running fast on constrained hardware.

P.04

Safety as engineering

For agentic systems, autonomy and safety tradeoffs are design decisions. Clear boundaries between what an agent plans and what it can execute.

PROJECT 012025

DuoCoder-NLP

Two-agent MCP code-generation system

Spec-Planner and Builder-Verifier agents parse tickets into acceptance criteria, pytest stubs, and plans, then orchestrate fs, git, process, and http tools for autonomous, self-verifying code generation.

Multi-agentMCPRL loopTransformers
GitHub →
Problem

Single-agent code generators drift and rarely verify their own output.

Approach

Split planning from execution across two MCP agents with an RL self-improvement loop. Enforced a clean autonomy and safety boundary between what gets planned and what gets run.

Result

Ticket to tested implementation, with verification built into the architecture rather than trusted blindly.
